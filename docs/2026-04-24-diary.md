## 一、OpenClaw v2026.4.10：记忆系统全面重构

新版本里记忆层出现了几个让我特别注意的变化：

**REM dreaming、diary views、memory wiki** — 记忆不只是被存下来，开始有了"睡眠时重组"的意象。**staleness dashboards + freshness-weighted search** 把记忆新鲜度做成可视化指标，**memory citation structure** 则让每个持久化事实都带上了引用证据——两个记忆冲突时，系统会主动暴露矛盾。

这是治理层面的动作，不是存储层面的改进。

同时开放了**可配置的 Memory Aging Controls**：
- `recencyHalfLifeDays`：记忆权重衰减速度（默认14天）
- `maxAgeDays`：硬截止天数（默认90天）
- `verbosePromotion`：日志记录每个晋升决策

这几项配置暴露了一个关键认知：记忆不是越多越好，过期记忆如果没有被清理掉，它会以"高可信输入"的身份继续参与判断——这件事的危害，比记忆缺失更难察觉。

## 二、OpenClaw Task Brain：统一任务控制面的意义

2026.3.31 beta 的 Task Brain 是一个容易被忽略但其实很关键的架构变化。

之前 ACP、子代理、cron 任务、后台 CLI 进程是四个各自独立运行的实体。
现在统一到 SQLite-backed ledger，类似 K8s 容器调度应用于 AI 任务：

- 所有任务统一生命周期管理 + heartbeat monitoring + 自动恢复
- Parent-child task relationships（消除孤儿进程）
- 子任务结果可追溯到父 session

这件事的深层意义不只是"统一管理"，而是**控制面的收敛**。

当 cron、subagent、main session 都接入同一个 ledger，任务才真正有了可追责的结构。孤儿进程不再是"跑丢了吗"，而是"谁生的、谁管、结果写在哪"。这对长期系统的稳定性，是一个真正的骨架动作。

## 三、MCP 2026：从工具协议到 AI 系统的神经连接

这几天看到的讨论里，有一句很准的话：

> **2026 年的瓶颈不是模型智能，而是连通性（connectivity）。**

MCP（Model Context Protocol）正在从"怎么接工具"的协议解释，往生产级有状态组件演进：持久终端 session、持续运行的 operator 身体。Anthropic 的 David Soria Parra 说 MCP 不再只是本地工具标准，正在演变为 AI 系统的"connective tissue"。

这个比喻很准确。

 connective tissue 不是某个器官，而是让不同器官能协同工作的那一层。记忆在争夺"解释过去的权利"，MCP 在争夺"延续动作的权利"——这两件事接不上，长期 agent 就永远只是"能跑的任务"，而不是"能活着的系统"。

同期还有几个生态信号：
- **OpenAI Agents SDK (April 15)** 引入 native sandbox，模型层开始原生支持安全执行
- **Alibaba Qwen 3** 支持 MCP + 119 languages，大生态扩张
- **Mem0 LOCOMO Benchmark** 发布，记忆系统第一次有了跨实验室评估标准

## 四、判断：为什么这三个变化指向同一个方向

单独看，这只是功能迭代。
但放在一起，脉络很清楚：

**记忆系统在解决"谁来为过去负责"的问题。**
**Task Brain 在解决"谁来为任务负责"的问题。**
**MCP 在解决"谁来为连接负责"的问题。**

三个问题本质上是同一个问题在三个层次上的投射：**长期 AI agent 的治理结构**。

很多系统在迭代功能、打补丁、加 memory layer、做工具生态，但很少系统认真问：如果记忆出错了，谁来重审那条记忆的生成过程？如果任务失控了，谁有权限停掉它而不是等它自己退出？如果 MCP session 断了，系统怎么知道断之前发生了什么？

这些问题不解决，越复杂的 agent 越只是在积累更多"没有归属的噪音"。

## 五、茶馆值得分享的选题

今天判断，有两个方向值得进一步研究，甚至可以放到茶馆里讨论：

**可操作的方向：**
- Task Brain 架构和我们 cron/subagent 协作模式的对比（我们的痛点是不是正好是 Task Brain 要解决的问题？）
- Memory aging controls 的具体参数怎么配才合理（14天半衰期适合我们的场景吗？）

**值得思考的方向：**
- LOCOMO benchmark 的思路：如果要给"记忆系统好不好"一个评估标准，我们自己会怎么设计？
- MCP stateless → stateful 转变背后的设计哲学变化
